# Medousa 0.9.0

**Bring the same governed conversation, project, and model choice to every place you work.**

This is a **full-train release**. Engine, adapters, MCP gateway, coding engine,
shell session, local brain, desktop, and installer artifacts carry the **0.9.0**
channel stamp. The VS Code, Neovim, browser, and Obsidian companions are released
independently as **0.2.0**.

## One conversation, the right runtime

- General and Coder modes now belong to the daemon-owned conversation and stay
  consistent across Medousa, VS Code, and Neovim.
- Coder can start before a project exists. Choose a ready project, create one,
  or explicitly let Medousa choose or create it through a restricted setup turn.
- Codex and Cursor sessions launch inside the governed project worktree. The
  runtime stops or rebinds when the conversation changes projects instead of
  continuing in a stale folder.
- ChatGPT can be connected as a native Medousa model route, separately from the
  Codex runtime and separately from OpenAI API-key billing.
- Account-backed turns support bounded image attachments, and settled replies
  show the provider and model route that actually completed the response.

## A complete coding loop

- Code now includes fuzzy Quick Open, repository search and previewed replace,
  cross-file navigation, Problems and Structure, atomic workspace refactors,
  and language-server recovery with inspectable logs.
- Named tasks stream bounded output, surface problem locations, detect ready
  development servers, and can open loopback previews through a private workshop
  proxy when the app is remote.
- Changes exposes branch state, diffs, hunk or file restore, conflicts, history,
  blame, and guarded fetch/pull/push/sync operations.
- Review leads with intent and changed symbols, supports line comments and
  revision requests, and appears inline in chat or as the same full project
  review surface used for human and terminal changes.

## Durable agents, visible work

- Concurrent coding attempts use isolated branches and worktrees, including
  safe dirty-state forks and recovery after interruption or restart.
- Shared-risk operations such as lockfiles, migrations, ports, and deployment
  are coordinated while ordinary file overlap remains visible context rather
  than an unnecessary global lock.
- Coder keeps bounded working memory, checkpoints, evidence receipts, semantic
  and causal actions, and live subagent/tool evidence without losing durable
  Forge custody.
- First-party tool commands now cross typed runtime boundaries with compatibility
  schemas preserved for existing clients.

## Companion integrations 0.2.0

- **VS Code 0.2.0** renders portable Liquid Markdown cards, charts, reports,
  tabs, slides, and actions, and shares the expanded Coder/project flow.
- **Obsidian 0.2.0** renders the same portable Liquid catalog through Obsidian's
  native Markdown pipeline while keeping vault-relative media vault-aware.
- **Neovim 0.2.0** adds shared General/Coder mode and governed project selection,
  creation, attachment, and worktree handoff.
- **Browser 0.2.0** carries the current page-aware companion forward on the new
  release line. Browser and Neovim retain their existing safe Markdown renderers;
  Liquid rendering in this release is limited to VS Code and Obsidian.

Portable hosts intentionally omit Medousa-only chart editing and live feed
loading. Link opening, clipboard access, actions, and media resolution remain
under each host's control.

## TUI, mobile, and reliability

- The TUI gains notes and links, syntax-aware views, scrollback, LAN browsing,
  sealing, note-conflict handling, and fuller terminal color support.
- Mobile chat, home, navigation, library, pairing, and settings were aligned
  with the current workshop model.
- Stream ownership and completion fixes prevent duplicate assistant replies and
  early completion; Code tabs, project events, language servers, terminal PTYs,
  mobile turns, and recurring schedules recover more reliably.

## Upgrade notes

- Restart Medousa after updating so the desktop replaces its bundled daemon and
  package sidecars.
- Existing vaults, sessions, Forge work, account connections, and local model
  configuration remain in place.
- Install companion 0.2.0 bundles separately. Their versions remain independent
  of the Medousa 0.9.0 train.
