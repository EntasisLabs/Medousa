# Medousa 0.9.1

**A Windows Forge / Code reliability patch for the 0.9 coding room.**

This is a **full-train patch release**. Engine, adapters, MCP gateway, coding
engine, shell session, local brain, desktop, and installer artifacts all carry
the **0.9.1** channel stamp. Companion integrations remain independently
versioned at **0.2.0**.

## Fixed

- Workshop sidecars (`medousa-session`, `medousa-code`), language servers, and
  Forge script spawns hide their Windows console windows. Closing a flashed
  console no longer kills the host mid-start.
- Shell session and coding engine health waits allow cold Windows starts, reap
  dead children, and clear stuck hosts after a timeout so Terminal and Review
  stop sticky `503` / “health timed out” failures.
- C# language sessions prefer `csharp-ls` when available, otherwise OmniSharp
  with solution/project binding, and initialize with workspace folders so
  non-entry `.cs` files load as project members instead of single-file
  “program” analysis.
- The desktop in-app browser no longer overflows past the shell on the right.
  Embed host sizing uses the full layout width (`min-w-0` / no `100vw`), and
  native bounds clamp to the window while correcting for content zoom.

## Upgrade notes

- Restart Medousa after updating so the desktop replaces the bundled daemon and
  workshop sidecars with the 0.9.1 packages.
- On Windows, reinstall **shell-session** and **coding-engine** from
  **Settings → Packages** if those packages were previously installed, then
  restart the workshop.
- For C# Problems, install `dotnet tool install -g csharp-ls` (preferred) or put
  OmniSharp on `PATH`, and open a folder that contains a `.sln` / `.csproj`.
- Existing projects, undertakings, workspace tabs, and terminal sessions are
  preserved.
