# Medousa 0.6.0 — Shared mode (profiles as members)

Living implementation notes for org-brain seats without login. Product language: **Shared mode**.

## Pillars

1. **Opt-in daemon mode** — personal installs stay as today; Shared mode is explicit.
2. **Profiles as members** — same registry; `root` admin + `general` org persona; QR binds device → profile.
3. **Attribution, not vault scoping** — one vault; stamp who acted.
4. **Dual session catalogs** — single-profile `session_catalog` + new `shared_session_catalog`; merge at list time.
5. **Shared chats** — agent context on `general`; speaker on each human event; out-of-turn ≈ workshop steer.

## Trust

- No SSO/login. Trust = pairing / device id.
- Loopback / privileged host ≈ root (org daemon in a controlled env).
- Portal bearer resolves bound `profile_id`; do not rely on process-global `set_active` for portal turns.

## Dual catalog

| Catalog | Use |
|---------|-----|
| `session_catalog` | Seat-private / personal chats (`profile_id` owner) |
| `shared_session_catalog` | Multi-member rooms (`member_profile_ids[]`, `agent_profile_id = general`) |

Create-time pointer: `catalog: single | shared`. List merges filtered rows for the caller’s bound profile.
