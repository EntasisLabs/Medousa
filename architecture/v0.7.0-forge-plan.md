# Medousa 0.7.0 — Forge core

Living implementation notes for Forge, Medousa's version-controlled work
lifecycle engine. Source plan: `.cursor/plans/bridge_agent_hub_gaps_110955a4.plan.md`
(revised through design review; amendments incorporated).

North Star: **a user-owned piece of work, executed by a replaceable agent inside
a governed environment, producing reviewable evidence and durable outcomes.**

## Layering

```text
User work → governed environment → executor → evidence → review → disposition
                                      ↑
                          ACP becomes one executor (later)
```

Forge owns durable user work; external agents are temporary executors attached
to that work. Forge is not "Git support for coding agents" — it is the
transaction and custody layer between a user's intention, one or more executor
attempts, durable evidence, human review, and a recoverable outcome.

**Governance = audit, not sandbox.** Violations and risks are evidence; they
never prove containment. Runtime sandboxing stays the executor host's job.

## Locked design decisions (from review)

1. **Authoritative metadata lives outside the worktree** — `{forge_root}/items/…`;
   worktrees contain only the user's repository. Portability via `export_bundle`,
   never by making the live worktree the database.
2. **Environment ≠ attempt** — one `GovernedEnv` per environment generation,
   many sequential `Attempt`s on it; a replacement executor continues the same
   work. New branch/worktree is an explicit restart/fork, not a retry property.
3. **Sealing is explicit** — Executing → Sealing → checkpoint commit → evidence →
   AwaitingReview. Dirty work becomes a durable Git object before review.
4. **Review binds to exact evidence** — digest + OIDs re-verified at disposition
   time; drift invalidates, approval never leaks.
5. **Forge is caller-driven, not a job runtime** — adapters own execution and
   report through the lease API; Forge owns leases and results. No `run()` trait
   defining the core contract (Stasis remains the durable-job system).
6. **Reconciliation uses leases, not PID files** — `LivenessProbe` trait answers
   what Forge cannot know; classification preserves, never auto-starts executors,
   never auto-deletes orphans.
7. **Evidence compares explicit OIDs** — provisioned `baseline_oid` vs sealed
   head, two-dot, never symbolic merge-base.
8. **Integration is serialized per repository** — repo lock, expected base OID,
   CAS ref update, `BaseAdvanced` typed error, no force update.
9. **v1 strategies** — `PreserveBranch`, `FastForwardOnly`, `ExportPatch`.
   Merge-commit and squash deferred until base-checkout/identity behavior is
   thoroughly tested.
10. **No singletons** — `Forge::open(forge_root)` is explicit; tests and future
    workshops construct independent instances.

**Versions vs Forge (locked verbs):** Versions *remembers* material; Forge *owns undertakings*. Targeting the vault root is a caller choice when Versions is on — Forge never auto-enables Versions and does not share Versions HTTP APIs. WorkCard / `/v1/workspace/cards` stays the activity board and is not Forge identity.
