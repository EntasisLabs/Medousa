# You and Context

**You** contains your profile and saved context: preferences, people, and facts. **Context** lets you browse saved session memory and its sources. Neither is the same as an imported Agent.

Related: [Architecture and terminology](guide:architecture) · [Sharing and phone](guide:sharing-phone) (Shared seats)

## You (Profiles)

Dock / More → **You**. Create menu:

| Action | Dialog |
|--------|--------|
| **Add information** | Save a fact or preference |
| **Add person** | Save a person and their relationship to you |
| **Add profile** | **New profile** (another hat / seat identity) |

Edit saved information: focus a card → **Edit** (prefilled with the saved value), or shelf **Correct or refine** / **Relationship** / **Value**.

Overflow: **Export/Import profile backup**, **Export identity notes**.

In Shared mode, seats bind profiles to one shared vault — see [Sharing and phone](guide:sharing-phone#shared-mode).

## Context

Open **Context** to start in **Browse**. Read saved moments, summaries, checkpoints,
decisions, and handoffs from sessions. Select a memory to see its stored content,
source session, and saved date. The memory list and search live in the left rail;
the main pane is the reader. Search matches loaded summaries and source sessions.

**Open source session** is available when the session is in the loaded chat list.
**Record details** reveals the original stored content. Related notes are compact
links: selecting one opens it in **Notes**, where documents are already rendered
and edited.

Switch to **Map** to explore the same saved memory and its relationships without
losing your selection. Click a memory or session to focus it, double-click a
session to expand its moments, or switch to **Browse** to read it. Note nodes are related links and open in **Notes**.

Context loads up to 200 recent moments. **Show more saved memory** reveals more
rows from that loaded list; **Refresh Context** refreshes it. Note metadata is
used only for links associated with source sessions. Context is saved memory,
not a receipt of the exact input used for an agent turn.

The memory reader presents STTP content as readable sections: decisions and why,
observations, handoffs, completed or remaining work, and blockers where saved.
Working context shows the recorded project, branch, and commit. Evidence and
references are the identifiers, files, and symbols stored with the memory;
tool completion alone does not establish a test verdict. Explicit memory
relationships open available targets in Context. Original STTP and technical
metadata remain under Record details. Records the reader cannot interpret retain their summary and original-record view.
