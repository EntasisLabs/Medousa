# Vault and notes

The vault is the workshop's memory on disk — notes, folders, and richer artifacts — browsed from the Work / Vault surface.

## Vault browser

- Folders on the left (or equivalent tree), file body on the right.
- Open notes as markdown with Live editing or preview.
- Wikilinks and Liquid fences work in vault notes the same way they do in this guide's reader.

Treat the vault as a workshop library, not a dump drawer. Name files so future-you (and the agent) can find them.

## Notes

- Create notes from the vault UI or agent tools.
- Dirty buffers stay with you across focus changes when the shell can stash them — don't panic if you switch panes mid-edit.
- Absolute "loose" files outside the vault can open when the app allows; prefer vault paths for anything the agent should own.

## Sticky note window

Pop a note into the **vault sticky** window when you want it beside another app. Always-on-top is available when you need the note to stay visible over other windows. Close hides; reopen from the titlebar / toolbar / Spotlight habits you already use for pop-outs.

## Chat ↔ vault bridge

Agents can read and write vault content when tools allow. Point at a note or selection when you want the turn grounded. Context chips in chat show when vault selection is attached.

```callout
tone: tip
title: Write for retrieval
body: Short titles, clear first lines, and stable paths beat clever naming. The agent searches what you leave it.
```

## Artifact kinds

Beyond plain notes you may see sheets, boards, slides, and other data-first surfaces. Open them from the vault or from custom views — see [Views and environments](guide:views-environments).
